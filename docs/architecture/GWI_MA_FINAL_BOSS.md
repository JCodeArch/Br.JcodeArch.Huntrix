# Gwi-Ma — card #41

Source: [41 — Criar Gwi-Ma](https://trello.com/c/lsykpVLG), final boss with phases and ending integration. `Resources/Enemies/GwiMa_Prototype` is an authored Demon-faction, 800-health geometric prototype using EnemyAgent and exactly one EnemyPatternController combat driver. Bind an explicit living target through EnemyAgent.TrySetTarget; no singleton player search or final film dialogue is introduced.

Three monotonic health phases: Opening (>70%), Pressure (<=70%), Finale (<=35%). Changes wait for Idle/Chasing, preserve health/target, and never cancel an existing attack windup/recovery. Opening alternates broad sweep and vertical slam; Pressure alternates long horizontal lanes and a tall column; Finale alternates three broad hits and a narrow long precision lane. The six attacks/patterns have distinct authored shapes/ranges/bursts/telegraphs. Damage, health, thresholds and timings are provisional balance. The existing shared pipeline handles walls, faction, parry, shields, invulnerability and deduplication.

Death stops the pattern, enters Defeated and reserves a once-only `EndingRequested(FinalBossOutcome2D)` event before any subscriber callbacks. Payload contains stable boss ID, authored ending cue ID and copied position. This is the typed boundary consumed by the later card #84 ending/cutscene integration; it does not invent dialogue or prematurely resolve Jinu's narrative. Event exceptions are isolated. Disable unsubscribes death and suspends the owned pattern; re-enable restores a suspended live pattern or reports an unreported death once. No revive/reset is implied.

Unity compilation, tests and full encounter playtest are deferred to the requested final validation phase. Pending scenarios: every phase pattern, threshold crossing/skipping, phase change at safe boundaries, death/disable during events, once-only outcome, disabled-state death and re-enable, 1–3 explicitly supplied targets, final ending consumer integration, readable telegraphs and mobile profiling.

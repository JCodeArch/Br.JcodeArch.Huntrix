# Contribution Rules

## Branching

Use feature branches for substantive work.

## Commits

Prefer focused commits using conventional prefixes:

- feat:
- fix:
- refactor:
- test:
- perf:
- docs:
- chore:

## Pull Requests

A PR should explain:

- objective;
- scope;
- architecture impact;
- tests;
- performance considerations;
- known limitations.

## Quality

Do not bypass agent gates or silently change architecture contracts.

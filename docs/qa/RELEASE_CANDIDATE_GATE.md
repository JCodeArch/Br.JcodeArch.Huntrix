# Release candidate evidence gate (#110)

Status: blocked pending real Unity/device/build/QA evidence. `scripts/check-release-candidate.py manifest.json` consumes schemaVersion 1, sourceCommit, tests {EditMode,PlayMode} XML paths, testProvenance JSON path produced by the runner (clean source commit + XML digests), builds [evidence JSON paths] for Android/iOS/Windows, performance {Entry,Standard,High} report paths with Unity buildGuid matching verified build evidence, deviceTierAssignments {Entry,Standard,High} with manually reviewed representative deviceModel values, qa {100,101,102,103,104} acceptance JSON paths and releaseApproval/approver. Paths are relative to the manifest. QA JSON requires status Passed, matching sourceCommit, reviewer, executedUtc and nonempty evidence references. Human review must verify those references and tie device reports/tests to the same build; JSON assertions are not independent proof.

Reports require nonunique hardware model/OS/CPU/GPU/RAM and captured scene/scenario metadata. The same hardware fingerprint cannot be relabeled as all three tiers; reviewer QA104 must approve representative hardware-to-tier assignments. No deviceUniqueIdentifier is collected. The gate rejects missing, failed, skipped, unmeasured and unapproved inputs. Passing it verifies the supplied evidence structure/digests, not app-store approval or independent authenticity. iOS export is a build pipeline milestone; signed archive/install acceptance remains required in mobile QA. Do not supply synthetic tooling fixtures as RC evidence. See docs/release/RELEASE_READINESS.md for open release requirements. No RC is approved or published by this implementation.

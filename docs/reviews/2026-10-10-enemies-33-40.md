## Findings corrected and verified statically

- Enemy initialization observes receiver initialization through explicit execution order rather than prematurely setting a live actor to `Dead`.
- Melee reserves its resolution guard before recovery notifications. A callback stopping/disabling/killing the source cancels subsequent contacts; inactive/dead hurtboxes and receivers are skipped. Accepted hits reuse `ResolveHit`, retaining factions, invulnerability, parry and protection.
- Support drain rejects nonfinite source/target positions. Health restoration requires living, enabled same-faction source and receiver, finite positive amount and authored maximum health; it neither revives nor pools health.
- External protection sources are additive to Mira sources. Each provider unregisters only its own memberships, and `Covers` validates source life, receiver eligibility, current range and duration.
- Horde completion uses an explicit natural-completion flag. Stopping, disabling or failing a partial wave does not report victory.
- Horde teardown releases list ownership before enemy callbacks and guards nested cancellation. Candidates are revalidated after initialization callbacks; encounter bootstrap also revalidates manager/source/component lifecycle before starting the wave. A failed horde start can leave a successfully spawned player for an explicit retry; atomic encounter startup is not claimed.
- Pattern events snapshot the starting burst count, isolate subscribers and invalidate the old cycle after a reentrant profile change. Post-tick guards reject a disabled controller or invalid target.
- Miniboss phase two survives disable/re-enable. Fresh instances start a fresh encounter; the phase driver runs before its pattern driver to avoid an opening telegraph being started and immediately reset by initialization.
- Jinu reconciles a receiver death missed while its observer was disabled, without replaying earlier cues. Narrative notifications snapshot stage/cue pairs, and phase configuration revalidates stage/life after callbacks.
- Shared profile/target configuration now reserves a configuration transaction before publishing the stopping state. Nested configuration and new actions are rejected during that transaction; new definitions commit only after callbacks leave the source enabled/alive/idle. Rival profile state is guarded and checked against the committed agent profile, preventing mismatched attack/rival data.
- Flying dive aborts when a retarget/stop cancels its agent action. The driver rechecks life/target/state after ticks and projectile initialization. Projectile contact reserves permanent consumption, snapshots attack/owner before callbacks, clips motion to remaining life/range and expires on owner teardown. Dive stopping distance uses a viable centered fixture reach instead of treating full hitbox width as a radius.
- Flying hover uses a target snapshot and validates enabled/living/same-target ownership after telegraph callbacks before moving. A callback retargeting to null cannot cause a hover dereference; returning to the authored hover band follows a completed dive.

## Structural and asset observations

Each authored enemy prefab has one behavior driver over the shared agent; support is intentionally stationary, and phase observers do not double-tick the agent. Explicit target/manager binding avoids global player discovery. Ground/elite/miniboss/support variants remain independent roots so existing faction/root ownership checks continue to apply.

Ray/overlap buffers are bounded and reject saturated sets conservatively. Per-receiver deduplication prevents multiple colliders from multiplying damage or support pulses. Horde limits and one-spawn-per-rendered-frame policy are safety bounds, not mobile performance measurements; pooling remains unimplemented.

The reviewed current enemy asset set had no unresolved GUID references or duplicate GUIDs, and new authored scripts/assets/prefabs had companion metadata. Static text inspection does not establish Unity import correctness, physics registration or visual readability.

`EnemyLab.unity` retains the existing Combat Lab camera/light/bootstrap and adds one encounter prefab instance. New prefab references and local scene/prefab fileIDs resolve textually. Existing engine/URP references inherited unchanged from Combat Lab require package import to verify; they are not new local-asset omissions. The encounter has a provisional floor and explicit stage/spawn positions, without physical controls or a visible player silhouette. Its appearance and execution remain unverified.

Final static verdict: **APPROVED for cards #33–#40 and the reviewed EnemyLab composition**, with no unresolved blocking source/asset finding in the final reviewed snapshot. Do not infer publication, merge or runtime approval from this verdict.
